# 操作トレーニング（シミュレーター）のシナリオ

`/machine-tools/{機種}/training/` のページは、このフォルダの `{機種のスラッグ}.json` から作られる。
1ファイル＝1機種＝1本のトレーニング。見本は `cnc-lathe.json`（NC旋盤）。

検査：`python3 build/sim_check.py data/mt/sim/{slug}.json`（ビルドでも同じ検査が走る）

## 誰のためのページか
- 工作機械を売る商社・メーカーの営業担当で、現場で機械を動かしたことがない人。操作の流れと「なぜそうするか」「間違えると何が壊れ、どれだけ止まるか」を体で覚える。
- 実際に機械を使う人（新人オペレータ、段取り担当、生産技術）。手順の理由と、典型的な事故・不良の原因と対策を整理し直す。

どちらにも通用するよう、**手順は現場の標準的なやり方**に合わせ、**理由と損失を具体的に**書く。

## ゲームの流れ
1. 画面上部に機械の図（動く）、下に操作盤とステップの問題が出る。
2. ステップを1つずつ進める。正しく操作すると機械の図が変化する（ドアが閉まる、主軸が回る、刃物が近づく、切りくずが出る…）。
3. 間違えると「トラブル」（incident）が起きる。図で衝突・飛散・発火などが再現され、何が起きたか／なぜか／損失／防ぐには を表示。ステップはやり直し。
4. 最後に得点（100点から減点：トラブルの重さ1＝−10、2＝−20、3＝−35、軽いミス（ng）＝−3）と評価（S≥95, A≥80, B≥60, C）、起きたトラブルの一覧を出す。
5. 「練習モード」ではヒントを表示、「本番モード」ではヒントなし。

## ファイルの形
```json
{
  "slug": "cnc-lathe",                 // ファイル名と同じ
  "visual": "lathe",                   // 下の表で機種ごとに決まっている
  "title": "NC旋盤の段取りと1個目の加工",   // トレーニングの名前（25字以内）
  "summary": "…",                      // ページの導入文（60〜220字）。何を体験できるか
  "level": 1,                          // 難しさ 1〜3
  "minutes": 12,                       // 1回の所要時間の目安（分）
  "job": "…",                          // 今日の仕事（ワーク・材質・寸法・状況）。2文以内
  "panel": ["power", "estop", …],      // この機械の操作盤に並べるボタン（6〜18個、下の一覧から）
  "steps": [ … 12〜18個 … ],
  "incidents": { "t_xxx": { … }, … },  // 12〜30件
  "safety": [ … 4〜7行 … ],            // 安全の基本
  "sales": [ … 4〜7行 … ]              // 商談で役立つ現場の視点
}
```

### ステップ（steps）の共通項目
| 項目 | 内容 |
|---|---|
| id | `s1`, `s2`, … （途中に足すときは `s7b` など） |
| phase | 段階名。例：始業点検／電源投入／段取り／補正／試運転／加工／計測／終業（機種に合わせて変えてよい。5〜8種類） |
| type | `check` / `panel` / `choice` / `input` / `order` / `jog` |
| title | 何をするか（「〜する」で終わる短い文） |
| text | 状況と問い。数値・条件を具体的に。2〜3文 |
| hint | 練習モードで出すヒント（答えそのものは書かない） |
| explain | 正解したときに出す解説。「なぜそうするか」 |
| pre | ステップが始まるときに図の状態を変える（例：ビビりが起きた状態 `{"chatter": true}`） |
| set | 正解したあとに図の状態を変える（下の「図の状態」） |

### ステップの種類
- **check**（点検・後始末のチェックリスト）：`items: [{"t": "…", "req": true}, {"t": "…", "req": false, "ng": "なぜ不要・危険か"}]`。4〜8項目、うち1〜2個は「やってはいけない／不要なこと」（req false＋ng）。必要な項目を選ばなかったとき：その項目に `"inc"` があればそのトラブル、なければステップの `"miss"` のトラブル。
- **panel**（操作盤のボタンを順に押す）：`seq: ["power", "estop", "hyd"]`（押す順）、`traps: {"cycle": "t_nohome"}`（今押すとトラブルになるボタン）。seq にも traps にもないボタンは軽いミス。seq と traps のボタンは必ず panel に入れる。
- **choice**（3〜4択）：`options: [{"t": "…", "ok": true}, {"t": "…", "inc": "t_xxx"}, {"t": "…", "ng": "なぜ違うか"}]`。正解はちょうど1つ。少なくとも1つはトラブルにつながる選択肢にする。正解をいつも1番目に置かない（画面では並べ替えるが、文の長さで正解がわからないようにする）。
- **input**（数値の入力）：`label`, `unit`, `ok: [最小, 最大]`, `cases: [{"lt": 値, "inc"|"ng": …}, {"gt": 値, …}]`（上から順に判定。ok の範囲と重ならないこと）, `ng`（どのcaseにも当たらず ok でもないときの説明）。計算が要る問題では、text に必要な数値をすべて書く。
- **order**（順番を決める）：`items` に**正しい順番**で2〜6個書く（画面ではシャッフルして出す）。間違えたら `inc` または `ng`。
- **jog**（ハンドルで工具を寄せる）：`axis`（"X" など）, `from`（最初のすき間 mm、0.5〜20）, `tol`（止めるべきすき間 mm 以下、0.005〜0.1）, `inc`（食い込んだときのトラブル）。プレイヤーはハンドルの倍率（×1=0.001mm, ×10=0.01mm, ×100=0.1mm）を切り替えて寄せる。工具とワークが近づく機種で1つ入れるとよい（任意）。

### トラブル（incidents）
```json
"t_slip": {"title": "把握力不足でワークが滑って抜けた", "sev": 3, "fx": "fly",
  "what": "何が起きたか（目に見える現象）",
  "why": "なぜ起きたか（操作のどこが誤りか、物理的な理由）",
  "loss": "損失（壊れる部品、不良、停止期間の目安、人への危険）",
  "prevent": "防ぐには（手順・確認・機能）"}
```
- `sev`：1＝軽微（アラーム停止・不良1個）、2＝中（工具破損・不良多数・半日〜数日の停止）、3＝重大（機械の破損・長期停止・人身の危険）。
- `fx`（図の演出）：`crash` 衝突（火花・揺れ）／`fly` 部品やワークが飛ぶ／`burst` といしの破裂／`fire` 発火／`smoke` 煙・過熱／`alarm` アラームで停止（赤ランプ）／`chatter` ビビり振動／`slip` ワークのずれ／`deform` 変形・寸法不良／`wirebreak` ワイヤ断線／`burn` 研削焼け（変色）／`leak` 液のあふれ・漏れ／`hazard` 人への危険（巻き込まれ・感電・やけど・目の障害）。
- 定義したトラブルは、必ずどこかのステップから呼ぶ。1つのトラブルを複数のステップから呼んでもよい。
- 少なくとも1件は sev 3。金額は書かない（「数日〜数週間の停止」のような表現はよい）。

## 図の状態（set / pre に使えるキー）
全機種共通：
| キー | 値 | 図での意味 |
|---|---|---|
| power | true/false | 操作盤の画面が点く |
| lamp | "off" / "yellow" / "green" / "red" | 信号灯（黄＝準備完了・停止中、緑＝自動運転中、赤＝異常） |
| door | "open" / "closed" | ドア |
| homed | true/false | 原点復帰済み |
| single | true/false | シングルブロック表示 |
| work | "none" / "set" / "done" | ワークなし／取付け済み／加工済み |
| clamp | true/false | ワークを固定（チャックを閉じる、バイスを締める、マグネットON など） |
| tool | "home" / "near" / "cut" | 工具（刃物・といし・ホブ・ヘッド）が退避位置／ワークの近く／加工中 |
| spindle | true/false | 主な回転（主軸・といし・ホブなど）が回る |
| coolant | true/false | クーラント（研削液・加工液）が出る |
| chips | true/false | 切りくず・火花が出る（研削は火花、放電・レーザは火花） |
| chatter | true/false | 振動している |

機種による追加（その機種でだけ図に出る。他で使っても無視される）：
| キー | 値 | 使う機種 |
|---|---|---|
| tail | true/false | 心押台を出す（lathe, turnmill, cylgrind） |
| bar | true/false | 棒材が入っている（swiss） |
| mill | true/false | 回転工具が回る（turnmill, swiss） |
| tilt | 0 / 45 / 90 | 傾き（5axis のテーブル、turnmill の工具主軸） |
| probe | true/false | タッチプローブを主軸に付けている（vmc, hmc, 5axis, gantry） |
| pallet | "A" / "B" | 加工位置にあるパレット（hmc） |
| dress | true/false | ドレッサがといしに当たっている（研削盤・歯車研削盤） |
| wspin | true/false | 工作物が回る（cylgrind, intgrind） |
| wire | true/false | ワイヤが張られている（wedm） |
| fluid | true/false | 加工槽に液が入っている（wedm） |
| gas | true/false | アシストガスが出ている（laser） |
| line | true/false | 搬送が動いている（transfer） |
| jaws | true/false | 生爪を成形済み（lathe, vtl） |

操作盤のボタンを正しく押したときは、ボタンに応じて図も変わる（例：`power`→電源ON、`door`→ドア開閉、`spindle`/`wheel`→回転、`sstop`/`wstop`→停止、`coolant`/`pump`→液、`chuck`/`magnet`→固定の切替、`cycle`→緑ランプ、`hold`→黄ランプ）。それ以外の変化は `set` で書く。

## 書き方のルール
- **公開されている一般的な知識だけ**で書く。特定の会社・工場・顧客の話は書かない。
- **メーカー名・製品名・制御装置の商品名・商標は一切書かない**（例：特定のNC装置名、合金の商標名）。「NC装置」「制御装置」「取扱説明書」と一般名で書く。Gコードなど制御装置で書き方が違うものは、具体的なコードを出さずに機能名で書き、必要なら「指令の書き方は制御装置により異なる」と添える。
- 数値（回転数、周速度、圧力、すき間、時間など）は**現実的で控えめ**な代表値にし、「〜程度」「一般に」を付ける。機械ごとに違うものは「取扱説明書の範囲で」とする。
- 法令・規格に触れるときは**WebSearchで条文を確かめてから**書く（例：研削といしの覆い・試運転・最高使用周速度・側面使用・特別教育は労働安全衛生規則、レーザの安全はJIS C 6802、加工油は消防法の危険物）。確かめられないことは書かない。
- 文はやさしい日本語で、1文を短く。専門用語は最初に出たところで（ ）で言い換える。例：「チャック圧（ワークをつかむ力）」。
- 1つのシナリオで、その機種らしさが出る操作を必ず入れる（例：研削盤＝といしの試運転・ドレッシング・スパークアウト、ホブ盤＝ホブの取付け向きと歯数・差動の設定、ワイヤ放電＝結線・比抵抗・中子の処理、レーザ＝焦点・ガス・反射材、トランスファー＝ライン起動前の全ステーション確認・異常時のロックアウト）。
- トラブルは「起きがちなミス」と「起きたら重大なミス」を両方入れる。新人がやりがちなこと、ベテランでも慣れでやってしまうことを優先する。
- `sales` は、その機械の現場の困りごとが**どの仕様・機能・周辺機器の話につながるか**を書く（売り込み文句ではなく、商談で聞くべきこと・話せること）。
- `safety` は一般的な安全の基本を書く。
